## 温度系统

大多技术博客默认一件事：文章发布时就是成品。这不符合真实认知的发展——一个判断从“我觉得”到“验证过”往往需要数月甚至更久，中间的状态通常无处安放。

温度是给这个中间状态的坐标——**由物态划定温区，再由多维证据自动校准**（越确定的思想，温度越低）：

| 状态 | 温区（基准） | 形态 | 含义 |
| :--- | :--- | :--- | :--- |
| `draft` | `17.0–19.8°C`（18.1°C） | 雾 | 想法刚成形，大概率仍有纰漏 |
| `exploring` | `11.0–16.8°C`（14.2°C） | 液态 | 正在实践探索，尚未定型 |
| `tested` | `6.6–10.8°C`（9.4°C） | 结晶中 | 已在真实项目中验证，仍有反例风险 |
| `stable` | `3.2–6.4°C`（5.4°C） | 结晶 | 长期沉淀，未遇到反例 |
| `deprecated` | `—` | 升华 | 观点已被推翻或升级 |

- **动态校准**：每篇笔记以所属物态的基准温度为起点，综合把握度（`confidence`）、文体（`category`）、正文认识论结构（未决问题升温，决策/失败证伪/图示降温），以及发布后的反向引用、日常轨迹（`/log`）提及、修订与附注在温区内自动微调，但绝不自动跨越物态边界——跨相态依然由作者确认后手动变更 `status` 并记入温度史。本地可运行 `npm run temp` 查看全站校准分解表。
- **全站温度**：取全部公开内容校准温度的中位数，随笔记状态与引用演化动态变化。
- **升华不删**：观点改变时，标记 `deprecated` 并指向新判断。删掉错误记录，等于抹去判断形成的真实过程。

## 这个站点不做的事

- 没有评论区
- 没有第三方追踪脚本与跨站埋点（仅在文章内页统计匿名去重的阅读人数，不做热门排行）
- 没有点赞、推荐算法与流量引导
- 不删除已经不成立的文章
- 不为了更新频率写缺乏实证的内容

> 可靠性不来自能做更多，而来自知道哪些事不该做。

## 温度系统

大多技术博客默认一件事：文章发布时就是成品。这不符合真实认知的发展——一个判断从“我觉得”到“验证过”往往需要数月甚至更久，中间的状态通常无处安放。

温度是给这个中间状态的坐标：

| 状态 | 温度 | 形态 | 含义 |
| :--- | :--- | :--- | :--- |
| `draft` | 19.5°C | 雾 | 想法刚成形，大概率仍有纰漏 |
| `exploring` | 14.0°C | 液态 | 正在实践探索，尚未定型 |
| `tested` | 8.4°C | 结晶中 | 已在真实项目中验证，仍有反例风险 |
| `stable` | 4.2°C | 结晶 | 长期沉淀，未遇到反例 |
| `deprecated` | — | 升华 | 观点已被推翻或升级 |

- **全站温度**：取全部公开内容温度的中位数，随笔记状态动态演变。
- **升华不删**：观点改变时，标记 `deprecated` 并指向新判断。删掉错误记录，等于抹去判断形成的真实过程。

## 这个站点不做的事

- 没有评论区
- 没有第三方追踪脚本与分析埋点
- 没有阅读量、点赞与推荐排行
- 不删除已经不成立的文章
- 不为了更新频率写缺乏实证的内容

> 可靠性不来自能做更多，而来自知道哪些事不该做。
